# legu stores ticket ids, never prose

A reader wants to record things to investigate, refactor or question later.
Those observations have state, get closed and reference each other — they are
tickets, and a ticket tracker (knot, GitHub issues, anything with an id)
already owns content and lifecycle. legu stores only a ticket reference: an id
anchored to a region, re-anchored by the same machinery as a review record.
Holding prose would grow a second issue tracker inside legu within a month,
with worse editing, searching and merging than any real one.
